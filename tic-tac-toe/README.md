# 井字棋作业说明

本作业要求你使用 **Qt Widgets** 完成一个可以运行的井字棋小游戏。重点不是界面多漂亮，而是把“窗口类 + 控件 + 布局 + 信号槽 + 简单状态管理”这些基础内容真正串起来。

## 1. 作业目标

你需要实现一个 3x3 井字棋程序，至少包含：

- 一个主窗口类 `MainWindow`
- 一个用于显示游戏状态的标签
- 一个 3x3 棋盘
- 一个重新开始按钮
- X / O 两名玩家轮流落子
- 胜负判断
- 平局判断
- 重新开始一局

## 2. 基本规则

井字棋规则如下：

- 棋盘是 3 行 3 列；
- X 先手；
- 两名玩家轮流在空格子里落子；
- 已经落子的格子不能再次落子；
- 任意一方在横向、纵向或斜向连成 3 个相同棋子，则这一方获胜；
- 如果棋盘填满后仍无人获胜，则为平局；
- 游戏结束后，棋盘不应继续变化；
- 点击重新开始后，棋盘清空，重新由 X 先手。

## 3. 界面要求

界面不需要复杂，但至少应包含：

```text
状态提示
3x3 棋盘
重新开始按钮
```

建议使用：

- `QLabel` 显示当前轮到谁或游戏结果；
- `QPushButton` 表示棋盘上的 9 个格子；
- `QPushButton` 表示重新开始按钮；
- `QGridLayout` 管理 3x3 棋盘；
- `QVBoxLayout` 组织整个窗口。

不要用大量 `move()` 写死 9 个按钮的位置。棋盘应使用布局完成。

## 4. 功能要求

### 4.1 落子

点击一个空格子时：

- 如果当前轮到 X，则显示 X；
- 如果当前轮到 O，则显示 O；
- 落子后切换到另一名玩家。

如果点击的格子已经有棋子，本次点击应当无效。

### 4.2 状态提示

程序应清楚显示当前状态，例如：

- 当前轮到 X；
- 当前轮到 O；
- X 获胜；
- O 获胜；
- 平局。

具体文字可以自行设计。

### 4.3 胜负判断

每次落子后，都应检查是否有人获胜。

你需要自己思考：

- 哪些位置连起来算获胜？
- 如何表示棋盘当前状态？
- 如何避免写出大量重复判断？

### 4.4 平局判断

如果没有人获胜，但棋盘已经没有空格子，则应判定为平局。

### 4.5 重新开始

点击重新开始按钮后：

- 清空棋盘；
- 游戏状态恢复为未结束；
- 重新由 X 先手；
- 状态提示恢复到初始状态。

## 5. 工程结构要求

你的工程应保持类似结构：

```text
tic-tac-toe/
├── CMakeLists.txt
└── src/
    ├── main.cpp
    ├── mainwindow.h
    └── mainwindow.cpp
```

说明：

| 文件 | 作用 |
|------|------|
| `CMakeLists.txt` | 描述如何编译 Qt 项目 |
| `src/main.cpp` | 程序入口 |
| `src/mainwindow.h` | 声明主窗口类 |
| `src/mainwindow.cpp` | 实现主窗口界面和游戏逻辑 |

主窗口类统一命名为：

```cpp
MainWindow
```

## 6. 实现提示

下面是提示，不是固定写法。

你可以考虑在窗口类中保存这些信息：

- 9 个棋盘按钮；
- 当前轮到谁；
- 游戏是否已经结束；
- 当前棋盘每个格子的内容。

你可以把逻辑拆成几个函数，例如：

- 处理某个格子被点击；
- 检查是否有人获胜；
- 检查是否平局；
- 重置游戏。

函数怎么命名、内部怎么写，可以自己决定。

## 7. 提交要求

提交时至少应满足：

- 程序可以正常编译运行；
- 点击棋盘可以正常落子；
- 能正确判断 X 获胜、O 获胜和平局；
- 能重新开始一局；
- 代码结构清晰，不要把所有逻辑都塞进 `main.cpp`；
- 使用布局管理棋盘和窗口；
- 源码中的类名、变量名、函数名使用英文。
